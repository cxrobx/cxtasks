That makes two -- cascades mandatory rather than optional: `projects::rename` has to -- carry these rows with it (invariant 11a), and `projects::delete` -- has to remove them — otherwise deleting project "X" and later -- creating a new "X" resurrects the old project's update log. project TEXT NOT NULL, author TEXT NOT NULL DEFAULT 'me', body TEXT NOT NULL, -- NULL = the update narrates without moving the dot. health TEXT, -- MILLISECOND precision, same reason as `task_comments.created_at` -- (gotcha #12): several updates posted inside one second would tie -- on `created_at` and render in random order. created_at TEXT NOT NULL DEFAULT (strftime('%Y-%m-%d %H:%M:%f','now')) )
